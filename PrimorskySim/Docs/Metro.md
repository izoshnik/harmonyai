# Metro (F)

## Что делает
Полноценное метро как часть мира: станции, вестибюли, входы, эскалаторы, платформы, тоннели, поезда по расписанию с диспетчеризацией, пассажиры-NPC, оплата, объявления, аварийные сценарии.

## Данные (Data/Metro, импорт в Data Assets)
- `UMetroLineAsset`: линия, цвет, упорядоченные станции, **трасса** — 3D-сплайн пути с пикетажем (chainage, м), стрелки, тупики. Трасса тоннелей не публикуется → строится как приближение между известными точками станций и помечается `approximated` в манифесте.
- `UMetroStationAsset`: object_id, линия, пикетаж оси платформы, тип станции, глубина, вестибюли → входы (координаты), турникеты, эскалаторы (кол-во, длина, направление по времени суток), платформа (длина, сторона дверей/островная, станция закрытого типа — если применимо).
- `UTrainTypeAsset`: тип состава (Балтиец), вагоны, двери (позиции вдоль вагона), динамика (разгон, торможение, макс. скорость), вместимость, звуковые банки, материалы салона.
- `UMetroTimetableAsset`: интервалы по времени суток и дням недели, оборот. Если официального расписания нет — интервалы помечаются `NEEDS_VERIFICATION`.

### Движение поезда
- Сервер интегрирует кинематику по пикетажу (фиксированный шаг 10 Гц), сигнализация — блок-участки (у поезда разрешённая скорость по свободности впереди). Позиция на клиенте — **интерполяция по пикетажу** на сплайне + реплицируемые фаза/скорость; без физической репликации каждого вагона.
- Игрок внутри поезда: базой движения является вагон (based movement), а не мир — исключает «выпадение» при сетевом дрожании.
- Двери: сервер переключает фазу; анимация на клиентах; посадка — триггеры дверных проёмов, вместимость — серверная проверка.

### Объявления
Генерируются по событиям (`ApproachingStation`, `DoorsClosing`, `Delay`) из шаблонов с переменными; голос — записанный/синтезированный заново, не копия оригинальных записей.

## Поезд «Балтиец»
- `PRM-ROLLINGSTOCK-BALTIETS`, статус NEEDS_VERIFICATION: индексы модификаций, составность, линии эксплуатации в 2026, габариты, двери — **не заполнены до проверки**.
- Визуальная цель: узнаваемая геометрия и интерьер именно «Балтийца» (по фото заказчика и открытым фото). Логотипы/фирменные обозначения — по `display_name_policy` (по умолчанию заменяются нейтральными).
- Варианты: головной/промежуточный вагон как варианты одного `UTrainTypeAsset`; составность — данными.
- Состав из нескольких типов поездов на линии поддерживается (тип — свойство рейса).

## Репликация
`FTrainSimState` реплицируется компактно (линия, пикетаж quantized, скорость, фаза, двери) только релевантным клиентам; dormancy, когда поезд вне релевантности всех клиентов.

## Расширение
Новая станция/линия = данные + запись манифеста; кода не требует. Новый тип поезда = `UTrainTypeAsset` + меши.
