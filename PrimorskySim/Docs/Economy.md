# Economy (J)

## Принцип
Деньги существуют только в серверном **Ledger** (двойная запись). Клиент, Blueprint и LLM не могут изменить баланс — только запросить операцию, которую сервер проверяет.

## Модель
- Счета: `Account{id, owner(entity), type: cash|bank|business|city_budget|escrow}`. Наличные — тоже счёт (с физическим представлением в инвентаре).
- Транзакция: `{tx_id (идемпотентный ключ), postings:[{account, amount}], reason_tag, refs}`; сумма проводок = 0. Деньги — целые копейки (int64), без float.
- Источники/стоки: зарплаты (от работодателя), покупки, аренда, налоги (в бюджет города), штрафы, ремонт, инфляция через ценовые индексы.
- NPC и игроки используют один и тот же Ledger; far-LOD NPC проводят агрегированные транзакции (дневные).

## Цены
- `UPriceIndex` по категориям товаров/услуг; базовые значения — Data Tables на основе реальных цен 2026 (источники в SourceRegistry, статус проверки как у объектов мира).
- Спрос/предложение: склады бизнесов (в т.ч. реальных POI) пополняются поставками (Jobs), цена корректируется в коридоре.

## Классы
`ULedgerSubsystem` (сервер, клиент к Ledger API), `UWalletComponent` (реплицирует владельцу только отображаемый баланс), `UPricingSubsystem`, `UPayrollSubsystem`, `UTaxSubsystem`, `UBusinessComponent`.

## Работа как часть симуляции (PrimJobs)
Заказ — цепочка задач между агентами (например: NPC заказал доставку → ресторан → приготовление → курьер → маршрут → доставка), исполнителем может быть NPC или игрок. Оплата — проводки Ledger по факту шагов. Профессии: курьер, такси, водитель автобуса, грузчик, работник ПВЗ, механик, электрик, строитель, врач, программист и др. — данные `UJobDefinition`.
