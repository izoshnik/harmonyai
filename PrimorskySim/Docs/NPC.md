# NPC Simulation (H)

## Масштаб — требует решения
Население района — порядка полумиллиона+ жителей (точная цифра — NEEDS_VERIFICATION, официальная статистика 2026). Варианты:
1. **1:1 записи жителей** как лёгкие данные (event-driven, без тиков), материализация по требованию. Реалистично для сервера при ~1–2 КБ на запись, но требует профилирования.
2. **Масштабный коэффициент** (например 1:10) для постоянных записей + статистический «фон» для плотности улиц.

Архитектура поддерживает оба (коэффициент — параметр). Решение за заказчиком (см. DataRequirements, «Решения»).

## Данные NPC (`FNpcRecord`, хранится в Persistence)
identity (id, имя, возраст, пол, внешность-seed, голос), дом (building_id + квартира/подъезд), работа (employer_id, должность, смены), финансы (ledger account ids), расписание (шаблон + отклонения), потребности (голод, усталость, социальное, досуг, здоровье), здоровье/травмы, отношения (граф: семья, друзья, коллеги — id + сила + история), знания и память (ключевые события с важностью и затуханием), предпочтения (магазины, транспорт, маршруты), транспорт (свой авто / ОТ / пешком), текущая задача (task id + прогресс), история событий (ограниченный журнал).

Внешность и имена генерируются из распределений (без копирования реальных людей). Реальные жители не воспроизводятся.

## Цикл жизни (far-LOD, `PrimSimCore`)
- Event-driven: агент «спит» до следующего события расписания (проснуться, выйти, сесть в автобус…). Очередь событий по времени мира, а не тик каждого агента.
- Задачи — граф шагов с ресурсами: `GoTo(место, способ)`, `Work(смена)`, `Buy(тип)`, `Ride(маршрут)`, `Visit(POI)`. Перемещения на far-LOD — по транспортному графу с оценкой времени (включая пробки и интервалы ОТ из текущего состояния симуляции).
- Утилитарный выбор (Utility AI) для свободного времени: потребности × предпочтения × доступность (часы работы POI, погода, деньги).
- Случайности (опоздание, болезнь, авария, смена работы) — стохастические события с параметрами из Data Tables.

## Переходы LOD (см. Architecture §4)
- Near (≈ до 150 м, в зоне видимости): Actor + StateTree/BT, физика, анимация, взаимодействия, восприятие (AIPerception).
- Mid (≈ 150–600 м): Mass entity, упрощённое движение по ZoneGraph/тротуарам, без восприятия.
- Far: только запись + событие.
- Promote: позиция = функция (текущий шаг задачи, прогресс по времени) → точка на графе → spawn из пула. Demote: только вне видимости всех игроков; состояние задачи сохраняется.
- Пороги — параметры AI LOD в Data Asset, зависят от бюджета кадра сервера.

## Классы
`UNpcRegistrySubsystem` (сервер, все записи), `UNpcScheduler` (очередь событий), `UNpcLodManager` (promote/demote, пулы), `ANpcCharacter` (near), Mass-процессоры `UNpcMoveProcessor`, `UNpcLodProcessor`, `UNpcMemoryComponent`, `UNpcRelationshipComponent`.

## Взаимодействие с другими системами
Транспорт (посадка/высадка, пассажиропоток метро), экономика (зарплаты, покупки — через Ledger), работа (цепочки заказов), закон (свидетели, память о событиях), диалоги (контекст для DialogueService).
