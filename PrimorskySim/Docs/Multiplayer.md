# Multiplayer (G)

## Топология
```
Клиенты (Win64) ──UDP──▶ Dedicated Server (UE, шард района) ──▶ Persistence API ──▶ PostgreSQL/PostGIS
                                     │                          ──▶ Ledger API (экономика)
                                     └──▶ DialogueService (LLM/STT/TTS, только intents)
```
- Шард = один экземпляр района. Ёмкость шарда (игроков) определяется нагрузочным тестом этапа 1; стартовая цель для замеров — 64, затем 128.
- Мультисерверная сетка одного района (зонирование) — не на старте; `PrimSimCore` спроектирован без UObject, чтобы far-симуляцию можно было вынести в отдельный процесс, общий для нескольких серверов.

## Авторитет
| Состояние | Владелец | Клиент может |
|---|---|---|
| Позиция персонажа | сервер (CharacterMovement с серверной коррекцией) | предсказывать |
| Транспорт | сервер (Chaos Vehicles, server-auth + client prediction для водителя) | предсказывать как водитель |
| Деньги, инвентарь, собственность, здоровье, розыск | сервер + Ledger/Persistence | только запрашивать |
| Взаимодействие | сервер исполняет `FInteractionRequest` после валидации (дистанция, LOS, права, кулдауны) | отправлять intent |
| Стрельба | клиент сообщает выстрел; сервер проверяет (боезапас, темп, геометрия с lag-компенсацией по истории позиций) | визуальные эффекты локально |
| NPC/трафик/метро/ОТ | сервер | только смотреть |

## Репликация
- Replication Graph или Iris (выбор по нагрузочному тесту): пространственная сетка, частота по дистанции, **dormancy** для статичных и далёких объектов.
- NPC near-LOD реплицируются как Actors; mid-LOD — только как упрощённые прокси (позиция/анимационный стейт пачками); far — не реплицируются.
- Interiors/Underground — relevancy по зоне (игрок на поверхности не получает пассажиров платформы).

## Анти-чит (базовый слой, архитектурный)
Server authority + валидация intent'ов; rate limits RPC; проверка скорости/телепортов; серверный пересчёт урона; экономика только через Ledger с идемпотентными ключами; логирование аномалий. Клиентский анти-чит (EAC/BattlEye) — решение этапа 3.

## Persistence
- Что сохраняется: игроки, ledger, собственность, транспорт игроков, состояние NPC-записей (identity, работа, дом, память ключевых событий, отношения), мировые изменения (разрушения длительные, постройки).
- Как: события накапливаются в `UPersistenceSubsystem`, пишутся батчами (по таймеру и на ключевых событиях), версии схем данных с миграциями. Деньги — синхронно через Ledger (см. Economy.md).
- Время мира непрерывно: при рестарте сервера far-симуляция «догоняет» пропущенный интервал аналитически (по расписаниям), а не пошагово.
