# Серверная автоматизация FunPay

HarmonyAI хранит отдельное подключение продавца, правила и товарный запас. Фоновая проверка работает без открытой вкладки.

## Подключение проекта

1. Выполнить миграцию `supabase/2026-11-23-funpay-automation.sql` в Supabase SQL Editor. Таблицы и функции доступны только серверной роли. Миграция сама не запускает обработку заказов.
2. В Vercel добавить две переменные окружения Production.
   - `FUNPAY_AUTOMATION_KEY` — 32 случайных байта в виде 64 шестнадцатеричных символов. Хранить резервную копию ключа в менеджере секретов. При его замене прежние записи нельзя расшифровать.
   - `FUNPAY_WORKER_SECRET` — отдельная случайная строка длиной от 32 символов. Скопировать то же значение в Supabase Vault под именем `funpay_worker_secret`.
3. В Vault добавить `funpay_worker_url` со значением `https://harmonyai.ru/api/util?op=funpay-worker`. Включить Supabase Cron и `pg_net`, затем выполнить в SQL Editor:

```sql
select cron.schedule(
  'harmonyai-funpay-worker',
  '* * * * *',
  $job$
    select net.http_post(
      url := (select decrypted_secret from vault.decrypted_secrets where name = 'funpay_worker_url'),
      headers := jsonb_build_object(
        'Content-Type', 'application/json',
        'Authorization', 'Bearer ' || (select decrypted_secret from vault.decrypted_secrets where name = 'funpay_worker_secret')
      ),
      body := '{}'::jsonb,
      timeout_milliseconds := 55000
    )
  $job$
);
```

Сгенерировать два независимых значения можно двумя вызовами `node -p "require('node:crypto').randomBytes(32).toString('hex')"`. После добавления переменных нужен новый Production deployment. Cron вызывает сервер раз в минуту. За один вызов обрабатывается один аккаунт продавца, поэтому при нескольких аккаунтах время реакции может увеличиваться. Для остановки фоновых запусков выполнить `select cron.unschedule('harmonyai-funpay-worker');`.

## Настройка продавца

Открыть **Настройки → Плагины → FunPay**, подключить свой аккаунт и нажать **Включить серверную автоматизацию**. После первой фоновой проверки можно публиковать лоты через чат. Для первой проверки используй разрешённый тестовый товар. Интеграция использует неофициальный клиентский протокол FunPay.

- `@FunPay настрой автоответ на сообщения: «Здравствуйте! Если у вас есть оплаченный заказ, напишите !order».`
- `@FunPay добавь команду !hours с ответом «Отвечаю ежедневно с 10:00 до 20:00».`
- `@FunPay когда покупатель подтвердил заказ, напиши: «Оставьте, пожалуйста, отзыв на заказ $order. Нам будет очень приятно!»`
- `@FunPay отвечай на отзывы: «Спасибо за отзыв!»`
- `@FunPay выключи автоответ на сообщения.`
- `@FunPay проверь серверную автоматизацию.`

Команды `!help` и `!order` включены по умолчанию. `$order` подставляет ссылку на заказ этого покупателя, `$status` — его статус, `$commands` — команды продавца. Публичные ответы на отзывы используют текст без переменных заказа.

Для нового лота укажи раздел, название, описание, цену и позиции выдачи. Если всем покупателям нужен один материал, явно укажи это и доступное количество продаж для разделов с полем наличия. Артикул `HA-…` добавляется к названию и сохраняется при правках через HarmonyAI. Если изменить название напрямую на FunPay, выдача по артикулу может остановиться. Штатная выдача существующих лотов остаётся доступной.

Первая проверка запоминает текущие заказы и чаты. Дальше отслеживаются свежие продажи и новые сообщения. Просьба об отзыве требует подтверждённого перехода заказа в закрытый и системного сообщения от FunPay, где подтверждение инициировал покупатель. При нехватке товара заказ ожидает пополнения. При неоднозначном результате отправки сервер сохраняет резерв и оставляет событие на проверку. Статус и последние такие события доступны через `@FunPay`. Перед отключением автоматизации проверь опубликованные лоты и незавершённые заказы в кабинете продавца.
